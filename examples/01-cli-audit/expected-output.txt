### [!] Low text contrast on `.hero-subtitle` — 1.03:1
- **Where:** `styles.css:8` · selector `.hero-subtitle`
- **Measured:** 1.03:1 (APCA Lc 0) (needs 4.5:1)
- **Why:** Text `#fbfbfb` on `#ffffff` measures 1.03:1 (APCA Lc 0). WCAG 2.2 §1.4.3 requires ≥ 4.5:1 for normal text.

### [!] Fixed 960px width on `.layout` with 0 media queries
- **Where:** `styles.css:44` · selector `.layout`
- **Measured:** width: 960px, 0 @media (needs fluid + breakpoints)
- **Why:** `.layout` is hard-coded to `width: 960px` and the project has no `@media` queries — the layout cannot adapt below 960px.
- **Impact:** On any viewport narrower than 960px the content overflows or is clipped; mobile is broken.
- **Fix:** Use `max-width: 960px; width: 100%` and add responsive breakpoints (sm/md/lg).
```diff
- width: 960px;
+ max-width: 960px; width: 100%;
```
- **Cites:** [Jakob's Law](https://lawsofux.com/jakobs-law/)

- **Why:** `.hero-subtitle` sets `font-size: 11px`, below the 14px minimum (16px recommended) for readable text.

### [*] 5 font families — use 1–2 max
- **Where:** `styles.css:36` · selector `.hero-title`
- **Measured:** 5 families: Playfair Display, Comic Sans MS, Bebas Neue, Lobster, Pacifico (needs 1–2 families)
- **Why:** 5 distinct `font-family` declarations found: `Playfair Display` (styles.css:36), `Comic Sans MS` (styles.css:37), `Bebas Neue` (styles.css:38), `Lobster` (styles.css:39), `Pacifico` (styles.css:40). More than two typefaces fragments the visual system.
- **Impact:** Too many fonts looks unprofessional, hurts brand coherence, and adds web-font payload.
- **Fix:** Keep one display family + one body family; delete the rest and map usages to the two kept families.
```diff
- font-family: Playfair Display;
- font-family: Comic Sans MS;
- font-family: Bebas Neue;
- font-family: Lobster;
- font-family: Pacifico;
+ font-family: var(--font-display);  /* headings */
+ font-family: var(--font-body);     /* everything else */
```
- **Cites:** [Occam's Razor](https://lawsofux.com/occams-razor/) · [Aesthetic-Usability Effect](https://lawsofux.com/aesthetic-usability-effect/)

### [*] <img> missing `alt` at SignupForm.jsx:9
- **Where:** `SignupForm.jsx:9` · selector `<img>`
- **Measured:** no alt attribute (needs WCAG 1.1.1)
- **Why:** `<img src="/logo.png" className="brand" />` has no `alt` attribute (WCAG 2.2 §1.1.1).
- **Impact:** Screen-reader users get no description; the image is announced as a filename or skipped.

```diff

+ <img alt="describe the image" src="/logo.png" className="brand" />
```

### [*] Form input has no associated label at SignupForm.jsx:17
- **Where:** `SignupForm.jsx:17` · selector `<input>`
- **Measured:** no label/aria-label (needs WCAG 3.3.2)
- **Why:** `<input type="email"    placeholder="Email address" className="body-copy" />` has no `<label for>`, `aria-label`, or `aria-labelledby` (a placeholder is not a label) (WCAG 2.2 §3.3.2 / §1.1.1).
- **Impact:** Screen-reader users cannot tell what the field is for; placeholder text disappears on input.
- **Fix:** Add a `<label htmlFor="…">` + matching `id`, or an `aria-label`.
```diff
- <input type="email"    placeholder="Email address" className="body-copy" />
+ <label htmlFor="field">Label</label>
+ <input id="field" type="email"    placeholder="Email address" className="body-co
```
- **Cites:** WCAG 3.3.2 Labels or Instructions (A) · WCAG 1.1.1 Non-text Content (A)
